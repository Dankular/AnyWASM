# SystemFunction036 target blocker

## Context

The selected D3D11-only `/MT` GLFWDemo reaches `UnhandledExceptionFilter` with
`STATUS_FATAL_APP_EXIT` (`0x40000015`) and exits with status 3. Its saved stack returns through
`GLFWDemo.exe+0x852F8`; disassembly at `0x1400852D5` follows a resolver path containing the
`SystemFunction036` string at `0x1400C2B78`, and the adjacent null-result path calls the fatal
runtime helper. The runtime maps `advapi32` to an HLE group but has no `advapi32` export lookup.
This makes the unresolved late-bound `SystemFunction036` the leading explanation for the observed
exit. The bounded trace now passes this resolver and next stops at `RtlPcToFileHeader`. After adding
that target-grounded helper, the trace reaches `RaiseException(0xe06d7363)` with an MSVC C++
`std::runtime_error`. That exception is a separate frame-dispatch gap; this design does not claim to
handle it.

## Requirements

- Resolve the exact `advapi32!SystemFunction036` name for static imports and `GetProcAddress`.
- On success, fill the requested guest buffer with cryptographically secure random bytes and return
  `TRUE`.
- A zero-length request succeeds without requiring a host entropy call.
- If memory allocation or a host entropy source fails, return `FALSE`; never substitute the
  process's deterministic PRNG.
- Do not copy partially generated bytes into guest memory when entropy acquisition fails.
- Support native Windows, native Unix-like builds, and the browser/Node WebAssembly host.
- Keep the public C ABI intact. Add the narrow `anywasm.random_fill` WebAssembly host import and
  supply it from `web/anywasm.js` using Web Crypto. Hosts without a cryptographic source fail closed.
- Verify the native HLE path, WASM host path, and selected target progression independently. Passing
  this blocker does not claim a renderer, frame, or game acceptance.

## Design

Add an `advapi32` HLE module. Its implementation stages the complete random buffer before writing
guest memory. Native Windows uses `BCryptGenRandom` with the system-preferred RNG; Unix-like native
hosts read from `/dev/urandom`. The WASM build requests bytes through a synchronous
`anywasm.random_fill` import, implemented by the JavaScript host with `crypto.getRandomValues` in
chunks no larger than 65,536 bytes.

The HLE returns `FALSE` for unavailable entropy, failed allocation, or a host provider failure.
Guest memory is only updated after the full request succeeds. The WASM host import returns false if
Web Crypto is missing or the temporary linear-memory range is invalid.

## Verification

- Rust tests cover export lookup, zero-length behavior, success, and fail-closed buffer preservation.
- A freestanding Win64 fixture loads `advapi32.dll` and resolves `SystemFunction036` with
  `GetProcAddress`; WASM smoke and browser runs execute it through the JS host.
- The bounded GLFWDemo trace is rerun with the same 30,000,000-instruction budget and VFS root.
  It passes `SystemFunction036` and `RtlPcToFileHeader`, then stops at the undispatched C++ throw.
  No frame or renderer is claimed.
